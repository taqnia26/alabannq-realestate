# TASK — admin password change from the dashboard, plus a deployment env document

Scope: only the two parts below. No new roles, no extra admins, no email sending, no password-reset-by-email, no 2FA, no other feature. No schema change: reuse the existing `admin_users` table (`password_hash`, `session_token_hash`, `session_expires_at`). If you believe a schema change is needed, stop and report instead of making it. Development database only — if you are asked whether to apply anything to production, answer no.

Why: today the dashboard cannot change the admin password, and `seed-admin` refuses to run once an admin exists, so a leaked or forgotten password can only be fixed with hand-written SQL on the server.

## Part 1 — change password

### API: `POST /api/auth/change-password`

In `artifacts/api-server/src/routes/admin-auth.ts`, reusing `lib/adminAuth.ts` (`currentAdmin`, `sameOrigin`, `hashPassword`, `verifyPassword`, `newToken`, `tokenHash`, `sessionExpiry`, `setSession`).

1. Body validated with zod: `currentPassword` (string, 1–1024 chars), `newPassword` (string, 12–1024 chars).
2. Requires a valid admin session (401 otherwise) and a passing `sameOrigin` check (403 otherwise).
3. Rate limit: 5 requests per minute per IP, same rule as `limitLogin` but with its own counter (turn the limiter into a small factory; login behaviour must stay identical). Over the limit: 429 with `Retry-After`.
4. Load the admin row for the session and check `currentPassword` with the existing `verifyPassword`. Wrong: 401 `{ "error": "كلمة المرور الحالية غير صحيحة." }`.
5. `newPassword` must differ from the current password and from the admin email (case-insensitive). No other complexity rules. Failure: 400 with a clear Arabic message. Keep this check in a small DB-free module with a `node:test` file in the style of `googleMaps.test.ts`.
6. On success, one update: the new `password_hash` from the existing `hashPassword`, plus a fresh session token hash and expiry. That replaces the only session slot, so every other session is revoked. Set the new cookie on this response so the current browser stays signed in. Respond 204 with `Cache-Control: no-store`.
7. Never log passwords, hashes or tokens.

### Dashboard UI

- In `src/admin/Dashboard.tsx`, in the `ad-sidebar-bottom` block above the logout button, add a "تغيير كلمة المرور" button (lucide `KeyRound`, `data-testid="button-change-password"`).
- It opens a dialog built on the existing pattern (`ad-overlay`, `role="dialog"`, `aria-modal="true"`): Escape closes it; focus moves into it and returns to the button on close. Three fields: current, new, confirm (`type="password"`, `autoComplete="current-password"` / `"new-password"`), a show/hide toggle on each, and a hint that the minimum is 12 characters.
- Client-side checks before sending: confirmation matches, length at least 12. Server errors appear inline with `role="alert"`. On success: short confirmation, fields cleared, dialog closed, admin still signed in.
- Arabic and RTL like the rest of the dashboard; reuse `ad-` classes and the existing `data-testid` naming (`input-…`, `button-…`, `error-…`). Do not change anything else in the sidebar or the editors.
