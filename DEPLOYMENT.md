# Build and environment reference

This document describes variables actually read by this repository. All values
below are fictional examples, not credentials or settings from a running server.
This task does not change deployment settings, provision accounts, run migrations,
or apply anything to a production database.

## API runtime

| Variable | Required? | Purpose | Example value |
| --- | --- | --- | --- |
| `DATABASE_URL` | Required | PostgreSQL connection used by `@workspace/db`; also required for the first-admin seed. Use the database appropriate to the environment being started. | `postgresql://example_user:example_password@db.example.invalid:5432/example_database` |
| `PORT` | Required | Positive numeric port on which the API listens. | `8080` |
| `NODE_ENV` | Optional; use `production` for production | Chooses production JSON logging instead of the development pretty-log transport. The development command sets it to `development`. | `production` |
| `LOG_LEVEL` | Optional; defaults to `info` | Pino log threshold. | `info` |
| `UPLOADS_DIR` | Required for image upload **and serving**; optional for the rest of the API | Absolute directory outside the API package's `dist` build output. Missing, relative, or build-output paths disable image operations; startup logs one error but does not stop the public site. The API process needs read/write permission to this directory. | `/srv/example/uploads` |

Run the API through the package's `start` command below so its working directory
is `artifacts/api-server`. Image-path validation resolves `dist` relative to that
working directory. Existing images need the same upload directory to remain
available between restarts; setting a path alone does not supply persistent storage.
An invalid upload configuration does not disable the site or external/static
images, but locally uploaded images cannot be uploaded or served.

## First-admin seed only

| Variable | Required? | Purpose | Example value |
| --- | --- | --- | --- |
| `SEED_ADMIN_EMAIL` | Required only when seeding | Valid email address for the **first** administrator. The script normalizes it to lowercase. | `first-admin@example.invalid` |
| `SEED_ADMIN_PASSWORD` | Required only when seeding | First-admin password; at least 12 characters. Stored as a salted scrypt hash, not plaintext. | `example-first-admin-password` |

The seed requires `DATABASE_URL` and the existing `admin_users` table. It refuses
to run if any administrator already exists. It is not a password-reset command.
Changing these seed variables after initialization does **not** change the
password stored in the database. A signed-in administrator changes their password
through the dashboard; this rotates the session and revokes previous cookies.

## Frontend build and preview

| Variable | Required? | Purpose | Example value |
| --- | --- | --- | --- |
| `PORT` | Required, including for a build | Vite configuration validates a positive numeric port; used by the development and preview servers. It is separate from the API process's port. | `5173` |
| `BASE_PATH` | Required | Vite's base URL for generated assets. The application derives its router base from the generated `import.meta.env.BASE_URL`. | `/` |
| `NODE_ENV` | Optional | Non-production Vite configuration may enable workspace-only tooling. Use `production` for a production build. | `production` |
| `REPL_ID` | Optional, development tooling only | If present in a non-production environment, enables workspace cartographer and development-banner plugins. Not required for a production build. | `example-workspace-id` |

`import.meta.env.BASE_URL` and `import.meta.env.DEV` are generated by Vite, not
additional variables to set. `BASE_URL` follows `BASE_PATH`; `DEV` controls the
error boundary's development-only details. There are no application `VITE_*`
variables read by the current frontend.

## Exact commands

Run these from the repository root with the documented variables supplied
securely by the intended environment. The development verification for this
change uses the development database only; do **not** run the seed against
production as part of this task.

```sh
# Full workspace type check
pnpm run typecheck

# API build: artifacts/api-server/dist/index.mjs
pnpm --filter @workspace/api-server run build

# Frontend production build: artifacts/alabnq-real-estate/dist/public
# PORT and BASE_PATH are required by vite.config.ts even during a build.
NODE_ENV=production PORT=5173 BASE_PATH=/ pnpm --filter @workspace/alabnq-real-estate run build

# First-admin seed, once only; supply DATABASE_URL and the two SEED_ADMIN_* secrets
pnpm --filter @workspace/api-server run seed-admin

# Start the built API; DATABASE_URL, PORT and (for images) UPLOADS_DIR must be set
NODE_ENV=production pnpm --filter @workspace/api-server run start

# DB-free password-policy unit tests
node --experimental-strip-types --test artifacts/api-server/src/lib/passwordPolicy.test.ts
```

Serve the frontend build as static files with an SPA fallback to `index.html`.
Route `/api` to the API service on the same public origin. Admin session cookies
are `HttpOnly`, `Secure`, `SameSite=Lax`, and scoped to `/api`; the public deployment
must therefore use HTTPS. No mail service, reset-by-email, new roles, additional
admin-management feature, or 2FA is introduced here.
